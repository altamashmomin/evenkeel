# Flask + gunicorn upper-bounded below the next major. The Pi runs
# `pip install -r requirements.txt` on every deploy, so an unpinned major
# (Flask 4, gunicorn 27) could land mid-deploy and break a live app. The
# ceilings sit above the current latest (3.x / 26.x), so they don't change what
# a deploy resolves today — they only block a FUTURE breaking major until it's
# tested and the ceiling raised deliberately (CODE-REVIEW 2026-08-08 Tier 2 #9).
flask>=3.0,<4
python-dotenv>=1.0
requests>=2.31
gunicorn>=21.2,<27
# gzip the SPA shell + static JS/CSS + API JSON on the fly (audit R1). The
# frontend critical path is ~211KB uncompressed → ~61KB gzipped (−71% first
# load); this handles the HTTP-correctness edges (static direct_passthrough,
# ETag/304, Vary, HEAD) that a hand-rolled after_request gets subtly wrong.
# gzip only — no brotli dep (COMPRESS_ALGORITHM='gzip' in app.py).
Flask-Compress>=1.14

# Agent layer (AGENT-DESIGN): the ledger_mcp read-tier sibling process.
# Upper-bounded: mcp 2.0 removed mcp.server.fastmcp.FastMCP, which
# ledger_mcp.py imports. A fresh install of an unbounded >=1.2 pulls 2.0
# and breaks the MCP server; pin to 1.x until ledger_mcp is ported.
mcp>=1.2,<2
httpx>=0.27
# Charlee's in-app Ask tab — the Anthropic tool-use loop (POST /api/ask).
# Only used at runtime by the endpoint; the loop tests mock the client.
# Upper-bounded below 1.0 so the pre-1.0 SDK's eventual major restructure can't
# land in a deploy uninvited (Tier 2 #9). Note: still pre-1.0, so 0.x minors
# flow through — tighten to a minor ceiling if a bump ever breaks /api/ask.
anthropic>=0.40,<1

# Transitive security floors. urllib3 and idna arrive via requests/httpx, whose
# own floors don't forbid the vulnerable versions — so without an explicit pin a
# fresh resolve can land on one, and `pip-audit -r requirements.txt` won't even
# flag it (it audits only declared deps). Floors set to the fixed releases:
#   urllib3>=2.7.0 — PYSEC-2026-142 (streamed-decompression resource exhaustion)
#                    + PYSEC-2026-141 (cross-origin redirect header leak via the
#                    low-level ProxyManager API).
#   idna>=3.15     — PYSEC-2026-215 (DoS via idna.encode() on pathological input).
# Ledger's own exposure is low/theoretical (outbound hosts are code-constant —
# SimpleFIN, Anthropic — not user-supplied, and it uses neither the streamed
# untrusted-decompression nor the ProxyManager path), but the patched floors are
# free defense-in-depth and keep the audit honest. Not upper-bounded — newer is
# fine. See the Aug 21 2026 health sweep.
urllib3>=2.7.0
idna>=3.15
